# Техническое задание
## Telegram-бот для загрузки медиаконтента из Instagram и YouTube

**Версия:** 1.1  
**Дата актуализации:** 10.10.2026  
**Статус:** Восстановлено по истории разработки; правки по `docs/mentor-handoff.md`, раздел 4  
**Проект:** `tg-bot`

> Документ описывает целевое поведение системы. **Разработка ведётся с нуля: кода прошлой версии нет**, сверять реализацию не с чем. Раздел 13 — справка о том, что работало в прошлой версии и где были проблемы, а не описание существующего кода.

## 1. Назначение проекта

Разработать Telegram-бота, позволяющего пользователям получать медиаконтент из Instagram и YouTube непосредственно в Telegram.

Бот предназначен преимущественно для использования в групповых чатах.

Основной сценарий использования:

1. Пользователь отправляет ссылку на поддерживаемую публикацию.
2. Бот автоматически определяет источник и тип контента.
3. Загружает оригинальный медиаконтент.
4. Отправляет его в Telegram.
5. При наличии оригинального описания прикрепляет его к публикации.
6. Удаляет временные файлы после завершения обработки.

Бот должен работать автономно на VPS и не требовать постоянного вмешательства администратора.

## 2. Поддерживаемые платформы

### 2.1. Instagram Reels

Поддерживаемые ссылки:

```text
https://www.instagram.com/reel/SHORTCODE/
https://instagram.com/reel/SHORTCODE/
```

Функциональные требования:

- Загрузка видео.
- Отправка видео в исходный Telegram-чат.
- Передача оригинального описания публикации.
- Поддержка ссылок с дополнительными URL-параметрами.
- Использование авторизованной сессии Instagram при необходимости.

### 2.2. Instagram Posts

Поддерживаемые ссылки:

```text
https://www.instagram.com/p/SHORTCODE/
```

Необходимо поддерживать три типа публикаций.

**Одиночная фотография**

- Скачать изображение.
- Отправить как фотографию Telegram.
- Сохранить оригинальное описание.

**Одиночное видео**

- Скачать видео.
- Отправить как видео Telegram.
- Сохранить оригинальное описание.

**Карусель**

- Определить все медиавложения.
- Скачать фотографии и видео.
- Сохранить порядок элементов.
- Отправить медиагруппу Telegram.
- Передать описание публикации.

Для каруселей, превышающих ограничения Telegram, необходимо предусмотреть разбиение на несколько медиагрупп.

### 2.3. YouTube Shorts

Поддерживаемые ссылки:

```text
https://www.youtube.com/shorts/VIDEO_ID
https://youtube.com/shorts/VIDEO_ID
```

Функциональные требования:

- Загрузка видеоролика.
- Предпочтение формата MP4.
- Выбор совместимого видеопотока и аудиопотока.
- Объединение потоков через FFmpeg при необходимости.
- Передача названия или описания ролика, если оно доступно.

### 2.4. Неподдерживаемые платформы

На текущем этапе не требуется поддержка:

- VK Видео.
- TikTok.
- Обычных видеороликов YouTube.
- YouTube-плейлистов.
- Instagram Stories.

Добавление новых источников должно быть возможно без существенного изменения основного приложения.

## 3. Обработка сообщений Telegram

### 3.1. Обнаружение ссылок

Бот должен анализировать входящие текстовые сообщения и находить ссылки на поддерживаемые ресурсы.

Необходимо учитывать:

- Сообщения, состоящие только из ссылки.
- Ссылки внутри произвольного текста.
- Дополнительные URL-параметры.
- Наличие завершающего `/`.
- Различные варианты доменов поддерживаемых сервисов.

### 3.2. Обработка ссылок

После обнаружения ссылки бот должен:

1. Проверить разрешение на обработку сообщения.
2. Определить платформу.
3. Определить тип публикации.
4. Вызвать соответствующий загрузчик.
5. Получить список медиафайлов и описание.
6. Отправить результат пользователю.
7. Освободить временные ресурсы.

Ошибки загрузки не должны приводить к остановке основного процесса бота.

### 3.3. Поведение при ошибках

Необходимо обрабатывать следующие ситуации:

- Публикация удалена.
- Публикация недоступна без авторизации.
- Истёк срок действия cookies.
- Instagram или YouTube ограничил запросы.
- Медиафайл недоступен.
- Превышен размер файла Telegram.
- Истекло время ожидания загрузки.
- Ошибка соединения с Telegram.
- Ошибка обработки видео через FFmpeg.

При возникновении ошибки пользователь должен получать понятное уведомление.

Технические подробности необходимо записывать в журнал.

## 4. Управление доступом

### 4.1. Владелец бота

У бота должен быть единственный основной администратор — владелец.

Его Telegram ID задаётся через переменную окружения:

```text
OWNER_ID
```

Владелец имеет право:

- Подтверждать новые группы. По умолчанию доступ запрещён: бот обрабатывает ссылки только в группах, явно разрешённых владельцем.
- Отклонять запросы на подключение.
- Просматривать список разрешённых групп.
- Управлять разрешениями.
- Получать административные уведомления.

### 4.2. Список разрешённых групп

Бот должен обрабатывать ссылки только в разрешённых группах.

Список разрешённых групп хранится в постоянном хранилище.

Формат — JSON-файл в томе данных (`data/`, раздел 8.4).

Данные должны сохраняться между перезапусками.

Запись — атомарная: данные пишутся во временный файл в том же каталоге, затем `os.replace` подменяет основной файл. Остановка контейнера или сбой посреди записи не должны оставлять наполовину записанный JSON и терять список групп.

### 4.3. Добавление в новую группу

При добавлении бота в неизвестную группу:

1. Бот определяет идентификатор группы.
2. Формирует запрос владельцу.
3. Владелец получает уведомление с информацией о группе.
4. Владелец может разрешить или запретить использование бота.
5. При подтверждении группа добавляется в список разрешённых.
6. При отказе бот выходит из группы.

### 4.4. Тайм-аут подтверждения

**Время ожидания: 60 секунд.**

Если владелец не принял решение за указанное время, бот должен автоматически покинуть группу.

Тайм-аут не должен блокировать обработку других сообщений.

Незавершённые запросы на подключение хранятся в постоянном хранилище вместе с моментом истечения: таймер в памяти пропадает при перезапуске, и без этого бот мог бы навсегда остаться в неподтверждённой группе.

При старте бот покидает группы, которых нет в списке разрешённых, — прежде всего группы с незавершёнными запросами.

Bot API не даёт получить список чатов, в которых состоит бот, поэтому дополнительно: при любом обновлении из группы, которой нет в списке разрешённых и по которой нет активного запроса, бот выходит из неё и пишет об этом в журнал.

### 4.5. Административные команды

Должны быть предусмотрены команды для:

- Получения статуса бота.
- Просмотра разрешённых групп.
- Удаления группы из списка.
- Получения справочной информации.

Названия команд определяются в плане этапа и перечисляются в справке бота.

## 5. Отправка медиаконтента

### 5.1. Видео

Видео должно отправляться как Telegram Video, если формат поддерживается.

Предпочтительные параметры:

- Контейнер MP4.
- Видеокодек H.264.
- Аудиокодек AAC.
- Разрешение не выше 1080p, если доступен подходящий вариант.

Перекодирование следует выполнять только при необходимости.

### 5.2. Изображения

Фотографии должны отправляться как Telegram Photo.

Необходимо учитывать ограничения Telegram на размер и формат изображения.

### 5.3. Медиагруппы

Для Instagram-каруселей использовать механизм Telegram MediaGroup.

Требования:

- Сохранение исходного порядка.
- Поддержка смешанных групп из фотографий и видео.
- Корректная обработка ограничений Telegram.
- Отправка оригинального описания.

### 5.4. Описание публикации

Оригинальное описание должно передаваться вместе с медиаконтентом.

При использовании подписи Telegram учитывать ограничение **1024 символа**.

Если описание превышает допустимый размер, необходимо предусмотреть безопасное сокращение либо отправку дополнительного сообщения.

Предпочтительный вариант — сохранять описание максимально полно.

## 6. Архитектура приложения

### 6.1. Общие требования

Язык разработки: **Python 3.12**.

Telegram-фреймворк: **aiogram 3**.

Основные зависимости:

- `yt-dlp` — загрузка контента.
- `aiohttp` — HTTP-запросы.
- `FFmpeg` — обработка видео.
- Стандартные библиотеки Python.

`yt-dlp` используется как библиотека Python, а не через запуск внешней команды.

Инструменты разработки:

- `uv` — окружение и зависимости; `uv.lock` хранится в git.
- `ruff` — форматирование и линтер.
- `pytest` — тесты.

Приложение должно иметь модульную архитектуру.

### 6.2. Слои приложения

- **Разбор ссылок** — поиск ссылок на поддерживаемые ресурсы в тексте сообщения и их нормализация (параметры, завершающий `/`, варианты доменов). Чистые функции без сети.
- **Маршрутизация** — по ссылке определяет платформу и тип публикации и выбирает загрузчик.
- **Загрузчик (порт)** — общий интерфейс загрузки и общие структуры результата (медиафайлы с типами и порядком, описание, временный каталог); реализации для Instagram и YouTube Shorts поверх `yt-dlp`. Остальной код зависит только от интерфейса, поэтому в юнит-тестах загрузчик заменяется фейком.
- **Отправка** — превращает результат загрузки в вызовы Telegram: видео, фото, медиагруппы с разбиением, подпись с учётом лимита.
- **Обработчики aiogram** — тонкий слой: приём обновлений, проверка доступа, вызов остальных слоёв, сообщения об ошибках.
- **Доступ и хранилище** — разрешённые группы и запросы на подключение (раздел 4).
- **Конфигурация** — чтение и проверка переменных окружения при старте.

Конкретная структура пакетов и файлов определяется в плане первого этапа. Структура прошлой версии приведена в разделе 13 только как справка.

## 7. Авторизация Instagram

### 7.1. Использование cookies

Для доступа к Instagram допускается использование авторизованной сессии.

Путь к файлу задаётся переменной окружения:

```text
IG_COOKIES_FILE
```

Расположение: `data/instagram.txt` в томе данных (раздел 8.4).

Формат: Netscape HTTP Cookie File.

Cookies берутся **от отдельного аккаунта Instagram, заведённого для бота**, а не от личного. Instagram запрещает автоматическую выгрузку и может ограничить или заблокировать аккаунт, с которого она идёт; потеря служебного аккаунта не затрагивает личный.

### 7.2. Безопасность

Файл cookies содержит конфиденциальные данные.

Требования:

- Не записывать значения cookies в журналы.
- Не передавать cookies пользователям Telegram.
- Ограничить доступ к файлу.
- Не включать cookies в исходный код.
- Не публиковать файл в Git.

Права на файл на сервере — `600`. Файл не попадает в образ Docker (`.dockerignore`) и подключается только через том данных.

### 7.3. Истечение сессии

Необходимо корректно обрабатывать ситуацию, когда Instagram перестаёт принимать cookies.

Ошибка авторизации не должна приводить к завершению процесса бота.

При ошибке авторизации Instagram бот уведомляет владельца о необходимости обновить cookies — не чаще одного раза за заданный интервал, чтобы серия неудачных запросов не превращалась в поток сообщений.

## 8. Развёртывание

### 8.1. Принцип

Бот разворачивается в Docker через `docker compose`. Причины:

- прошлая версия пропала вместе с VPS, потому что всё жило только на сервере (виртуальное окружение в `/opt`, вручную настроенная служба systemd); теперь на сервере лежат только данные и секреты, всё остальное воспроизводится из репозитория;
- в образе сразу есть FFmpeg и зафиксированные версии зависимостей (`uv.lock`) — сервер не нужно настраивать;
- политика `restart: unless-stopped` обеспечивает автозапуск после перезагрузки сервера и перезапуск после падения — отдельная служба systemd не нужна.

### 8.2. Сервер

Целевая ОС: Ubuntu 24.04 LTS с Docker Engine и плагином compose. Больше на сервере ничего не устанавливается.

Сеть: long polling — бот сам обращается к Telegram, входящих соединений нет. Домен, TLS-сертификат и открытые порты не нужны.

### 8.3. Файлы развёртывания в репозитории

- `Dockerfile` — образ на Python 3.12 с FFmpeg; зависимости ставятся через `uv` строго по `uv.lock`; процесс работает не от root.
- `compose.yaml` — сервис бота: `restart: unless-stopped`, переменные из `.env`, том `./data`, ограничение размера журналов Docker.
- `.env.example` — список переменных без значений (`BOT_TOKEN`, `OWNER_ID`, `IG_COOKIES_FILE`, …).
- `.dockerignore` — `.env`, `data/`, `.git`, `.venv` и всё, что не должно попасть в образ.

### 8.4. Данные и секреты

- `.env` — токен бота и другие секреты; на сервере с правами `600`; в `.gitignore`. В репозитории — только `.env.example`.
- Том `./data` — список разрешённых групп, незавершённые запросы на подключение, `instagram.txt`. Это всё состояние бота.
- Резервная копия `data/` и `.env` хранится вне VPS. Восстановление из копии проверяется хотя бы один раз (на чистом сервере или в отдельном каталоге): непроверенная копия не считается копией.

### 8.5. Восстановление на новом сервере

1. Установить Docker.
2. Выполнить `git clone` репозитория.
3. Положить `.env` и `data/` из резервной копии.
4. Выполнить `docker compose up -d`.
5. Проверить по журналу запуск и отправить тестовую ссылку в разрешённую группу.

### 8.6. Журналирование

Использовать стандартный Python logging.

Журналы пишутся в stdout/stderr и читаются через `docker compose logs`; ротацию выполняет Docker (ограничение размера в `compose.yaml`).

Журналы должны позволять определить:

- Запущен ли бот.
- Получает ли сообщения.
- Какая платформа обрабатывается.
- Успешна ли загрузка.
- Причину ошибки.
- Результат отправки в Telegram.

Конфиденциальные значения не должны попадать в журналы.

## 9. Надёжность

### 9.1. Изоляция ошибок

Ошибка отдельной публикации не должна останавливать бота.

Необходимо обрабатывать исключения на уровне каждого запроса.

### 9.2. Временные файлы

Каждая загрузка должна использовать отдельную временную директорию.

После обработки необходимо удалять временные файлы независимо от результата отправки.

### 9.3. Параллельная обработка

Бот должен сохранять способность принимать новые сообщения во время загрузки контента.

Блокирующие операции необходимо выполнять так, чтобы они не останавливали event loop.

### 9.4. Ограничения ресурсов

Необходимо предусмотреть:

- Тайм-ауты загрузки.
- Контроль размера файлов.
- Ограничение количества одновременных загрузок.
- Очистку временных данных.
- Защиту от повторной обработки одинаковых запросов.

Конкретные лимиты подлежат определению при реализации.

## 10. Обновление зависимостей

Обновления должны выполняться контролируемо. Версии Python-зависимостей зафиксированы в `uv.lock`, системных — базовым образом в `Dockerfile`.

Порядок обновления:

1. В отдельной ветке обновить зависимость (например, `uv lock --upgrade-package yt-dlp`), при необходимости — базовый образ.
2. Прогнать линтер и юнит-тесты (CI).
3. Собрать образ и прогнать дымовые тесты на реальных ссылках (раздел 11).
4. Слить изменения; на сервере — `git pull` и `docker compose up -d --build`.
5. Проверить по журналу запуск и обработку тестовой ссылки.

Откат — возврат к предыдущей ревизии репозитория и `docker compose up -d --build`: `uv.lock` этой ревизии воспроизводит прежние версии.

Особое внимание уделить `yt-dlp`, поскольку изменения Instagram и YouTube могут нарушать работу загрузчиков.

## 11. Тестирование

Тестирование ведётся на двух уровнях.

**Юнит-тесты** (`pytest`, без сети). Загрузчик спрятан за интерфейсом (раздел 6.2), в тестах вместо него — фейк, возвращающий заданные файлы или ошибки; Telegram тоже заменяется фейком. Покрывают разбор ссылок, маршрутизацию, разбиение медиагрупп, подписи, доступ и хранилище, обработку ошибок. Запускаются локально и в CI на каждый PR.

**Дымовые тесты** — на нескольких реальных публичных ссылках (Reel, пост с фото, карусель, Shorts) через настоящий `yt-dlp`. Запускаются вручную (например, после обновления зависимостей) и по расписанию раз в сутки на сервере бота, с отчётом владельцу. На сервере, а не в CI: cookies Instagram в CI не передаются, а без них и с адресов облачных CI Instagram отвечает иначе. Падение дымового теста — первый сигнал, что Instagram или YouTube изменили формат и пора обновлять `yt-dlp`.

Сценарии ниже распределяются по этим уровням в плане этапа: каждый — юнит-тест с фейком, дымовой тест или ручная проверка.

### 11.1. Instagram Reels

Проверить:

- Публичный Reel.
- Reel с описанием.
- Reel с дополнительными URL-параметрами.
- Недоступный Reel.
- Ошибку авторизации и уведомление владельцу об истёкших cookies.

### 11.2. Instagram Posts

Проверить:

- Одну фотографию.
- Одно видео.
- Карусель фотографий.
- Карусель видео.
- Смешанную карусель.
- Публикацию с длинным описанием.

### 11.3. YouTube Shorts

Проверить:

- Обычный Shorts.
- Видео с раздельными аудио- и видеопотоками.
- Недоступный ролик.
- Ошибку загрузки.

### 11.4. Telegram

Проверить:

- Обработку ссылки в разрешённой группе.
- Игнорирование сообщений в запрещённой группе.
- Запрос владельцу при добавлении в новую группу.
- Подтверждение доступа.
- Отклонение доступа.
- Автоматический выход через 60 секунд.
- Работу после перезапуска сервера.
- Выход при старте из групп с незавершённым запросом.
- Выход из неразрешённой группы при обновлении из неё.
- Сохранность списка групп при прерванной записи.

### 11.5. Отказоустойчивость

Проверить:

- Ошибку Instagram.
- Ошибку YouTube.
- Недоступность Telegram API.
- Ошибку FFmpeg.
- Недостаток свободного места.
- Несколько одновременных запросов.

## 12. Критерии приёмки

Система считается соответствующей ТЗ, если:

1. Бот автоматически запускается после перезагрузки VPS.
2. Получает и обрабатывает сообщения Telegram.
3. Скачивает поддерживаемые Instagram Reels.
4. Обрабатывает фотографии, видео и карусели Instagram.
5. Скачивает YouTube Shorts.
6. Передаёт описание оригинальной публикации.
7. Соблюдает ограничения доступа.
8. Запрашивает разрешение владельца при подключении новых групп.
9. Автоматически покидает неподтверждённые группы через 60 секунд.
10. Не прекращает работу при ошибке отдельной загрузки.
11. Удаляет временные файлы.
12. Не раскрывает конфиденциальные данные.
13. Сохраняет настройки и разрешённые группы после перезапуска.
14. Позволяет диагностировать ошибки через журналы.
15. Разворачивается на чистом сервере по разделу 8.5; восстановление из резервной копии проверено.
16. Дымовые тесты выполняются ежедневно и сообщают владельцу о сбоях.
