# Передача проекта tg-bot новой сессии наставника

Этот файл — стартовый контекст для новой сессии (Cowork), в которой наставник сопровождает разработку бота.
Он написан в сессии, где шёл проект Garage (iOS + Vapor, `~/Developer/TestProj`), и переносит оттуда
договорённости, опыт и решения. После подготовки платформы файл можно удалить или оставить как историю.

## 1. Как мы работаем

- Андрей работает в Claude Code (desktop) на Mac, в каталоге `~/Developer/tg-bot`.
- Наставник (сессия Cowork) не пишет код проекта сам: проверяет файлы, даёт промпты для агента Claude Code,
  разбирает планы и отчёты, объясняет «почему». Объяснения — развёрнутые, на русском.
- Цикл этапа: plan mode (Opus) → план в `docs/plans/` → наставник проверяет план → реализация частями,
  каждая часть — отдельная сессия (Sonnet) → swift/py-ревьюер на diff → PR → `/finish-stage` (журнал, уроки).
- В master — только через PR; `git push` — через подтверждение; force-push и push в master запрещены.

## 2. Что переносится из Garage (проверено на 12 этапах)

Практики:
- **Разведка с остановкой (шаг 0).** Всё неизвестное (лимиты Telegram, поведение yt-dlp, формат каруселей)
  сначала проверяется пробой — запуском, а не чтением документации. После проб — стоп и отчёт.
- **Проверка на зубы.** Для ключевой логики: временно сломать строку → назвать упавшие тесты → вернуть.
  Тест, который ни разу не видели красным, ничего не доказывает. По одной мутации за прогон.
- **Положительный контроль.** Проверка «X отсутствует» должна уметь найти X там, где он есть, иначе зелёный
  результат ничего не значит (урок `pipefail`).
- **Ложное покрытие — главный враг.** Проверка, которая не может упасть, хуже отсутствующей.
- **Терпимый читатель.** Внешние данные (Telegram Update, ответы yt-dlp) могут содержать незнакомые поля и
  типы — бот их пропускает с логом, а не падает.
- **Односторонние двери.** Строго проектируется то, что трудно поменять потом (формат хранилища, развёртывание,
  секреты); внутренний код — просто, рефакторинг под защитой тестов.
- **Правило — просьба, хук/deny/тест — гарантия.** Повторяющееся нарушение правила превращается в запрет.
- **Стоимость = шаги × размер контекста.** План — двухуровневый (основной файл + `-notes.md`), читается по
  разделам; каждая часть этапа — отдельная сессия; ревью и правки по нему — в начале свежей сессии.

Механизмы (лежат в `.claude/`, скопированы из Garage, требуют адаптации — см. раздел 5):
- хуки: `deny-shell-writes.sh` (универсален), `session-context.sh` (универсален), форматирование;
- агенты: `check-runner` (Haiku, запускает проверки, отчёт по коду возврата), ревьюер;
- скиллы: `new-feature`, `finish-stage`.

## 3. Решения, принятые до старта

- **Язык и стек:** Python 3.12, aiogram 3, yt-dlp (как библиотека, не через внешнюю команду), FFmpeg.
  Инструменты: `uv` (окружение и зависимости, `uv.lock` в git), `ruff` (формат и линт), `pytest`.
- **Развёртывание: Docker + docker compose** (решение наставника по просьбе Андрея). Почему:
  - прошлый бот пропал вместе с VPS, потому что всё жило только на сервере (venv в `/opt`, ручной systemd);
  - в образе сразу есть FFmpeg и зафиксированные версии зависимостей — сервер ничего не нужно настраивать;
  - восстановление на новом VPS: установить Docker, `git clone`, положить `.env` и cookies, `docker compose up -d`;
  - `restart: unless-stopped` закрывает автозапуск и перезапуск после падения — systemd-юнит не нужен;
  - тот же подход потом пригодится для сервера Garage.
- **Сеть:** long polling — бот сам ходит к Telegram, входящих соединений нет; домен, TLS и открытые порты не нужны.
- **Данные:** том `./data` (список групп, cookies); резервная копия; проверка восстановления хотя бы раз.
- **Секреты:** `.env` (`BOT_TOKEN`, `OWNER_ID`, …) и `data/instagram.txt` — в `.gitignore` и в `deny` на чтение
  (`Read(**/.env)`, `Read(**/data/**)`); в репозитории — `.env.example` без значений.
- **Доступ:** по умолчанию всё запрещено, пока владелец не разрешил группу.

## 4. Правки к ТЗ (ТЗ сохранить в `docs/spec.md`)

1. Раздел 13 «Текущее состояние» переименовать в «Что было в прошлой версии» и прямо написать:
   **разработка с нуля, кода нет**. Иначе агент начнёт искать и «сверять» несуществующий код.
2. Пункт 4.5 (автоматически разрешать ранее подключённые группы) — **удалить**: это дыра в доступе, а список
   прежних групп утрачен вместе с сервером.
3. Раздел 8 переписать под Docker compose (см. выше); структуру `/opt/tg-bot/venv` убрать.
4. JSON-хранилище групп — атомарная запись (временный файл + `os.replace`).
5. При старте бот покидает группы, которых нет в списке разрешённых (таймер ожидания мог пропасть при перезапуске).
6. Cookies Instagram — **от отдельного аккаунта**, не личного: Instagram запрещает автоматическую выгрузку
   и может заблокировать аккаунт. Уведомлять владельца об истёкших cookies.
7. Тестирование — два уровня: юнит-тесты без сети (загрузчик за интерфейсом, в тестах фейк) и дымовые тесты
   на нескольких реальных публичных ссылках — вручную и по расписанию (раз в сутки), с отчётом.
